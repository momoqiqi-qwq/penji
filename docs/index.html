01 / 链路

一条链路，只留一种数据来源

传感器读数、农事记录、投入品台账在同一个批次上汇合；二维码是这个批次的出口。每一环都能回答「这条数据是谁采的、从哪来的」。

01 · SENSE

传感器

MQTT 直连 / 云开发 watch / 演示兜底，四参数一帧

02 · STORE

readings 集合

服务器时间为准，900 ms 防重放，日聚合幂等

03 · DERIVE

环境评价 / OPI

与农事记录、投入品台账在批次上汇合

04 · ARCHIVE

批次档案 + 二维码

一个批次一张码，档案随记录生长

05 · LOOK UP

扫码的两端

消费者看过程，采购商核验并录入检测

02 / 三种身份

同一份数据，三种看法

身份决定你看到什么、能改什么。权限判定只有一处：auth.canEdit / canUpload / canReview / canInspect。

农户

FARMER · 土地的主人

  • 地块与批次建档，一季一档
  • 农事记录与投入品台账，随手一记
  • 本地规则库的农技诊断，离线可用
  • 环境实况与曲线，来源如实标注

演示账号 · 张老汉 F-001 / 王秀英 F-002 / 李建国 F-003 / 赵桂花 F-004

消费者

CONSUMER · 扫码的人

  • 扫一张码，进这一批菜的档案
  • 看 OPI、检测报告、农事与环境曲线
  • 评价与反馈，直接影响农户信用
  • 不用注册成农户，扫码即看

演示账号 · 任意（不绑定农户与采购商）

采购商

BUYER · 收菜的人

  • 主推地块按成熟倒计时排序
  • 看中就预订购，锁住这一茬
  • 批次核验：同一张码，另一套视角
  • 录入食品检测，不合格一票否决

03 / 能力

六件事，做扎实

不做大而全。传感器、档案、信用、评价、诊断、核验，每一件都要能被追问到「你这个数哪来的」。

四参数，来源必须说清

空气温湿度、光照、土壤湿度。三种来源各有一个标签：【实时直连真实数据】 / 【云端采集真实数据】 / 【演示模拟数据】，不混用、不省略。

sensors.sourceLabel

批次档案与二维码

一个批次一条档案、一张码。二维码编码器是手写的最小实现，不引第三方库，也不上传任何数据到外部服务。

utils/qrcode.js

农户信用分

0–100，六档 AAA→D。履约意愿 20 / 履约能力 40 / 履约行为 40；严重失信每条 −15，经核实投诉 −8。全项目只有一个算法。

credit.evaluateFarmer

OPI 有机生产评价

环境监测 30 / 种植过程 50 / 质量保障与追溯 20，对标 NY/T 3667-2020。连续采集满 30 天才给满分——数据不够就如实扣。

ai.calcOPI

农技诊断

本地规则库 + 知识库，把症状、环境读数、作物阶段放在一起给建议。田里没信号也能用，不上传照片也能问。

diagnose.js + diag-kb.js

采购商核验

采购商扫同一张码，看到的不是营销页而是核验页：投入品、转换期、缓冲带、检测结果逐项过，然后录入自己的检测。

store.getOrganicCompliance

05 / 设计系统

四条硬规则

全部 token 在 app.wxss 顶部。规则不是为了好看，是为了让 16 个页面看起来像一个人画的。

01

绿色只有四级

ink / green / lime / green-mist。要第五种绿，说明设计错了。

02

字号只有六级

20 / 22 / 24 / 26 / 32 / 40 rpx。页面里不会出现 27rpx 这种数字。

03

阴影永远两层

近处一层实、远处一层散。单层阴影一定显廉价。

04

圆角只用四档

r-sm / r-md / r-lg / r-xl，不随手写像素值。

唯一例外是角色色：农户绿 / 消费者蓝 / 采购商金，只用于「这是谁」，不进入业务语义。

06 / 边界

现在还不是成品

一个溯源产品最不能做的事，是把演示数据说成真实采集。所以这里把没做完的部分也列出来。

P0数据层仍是本地 mock

多设备看到的是各自的本地数据。要上线，得按 store.js 的接口逐个替换为云开发实现。

P0照片不落云存储

选完图只存了临时路径，重进小程序即失效。接 wx.cloud.uploadFile 后写回 fileID。

P1设备密钥是字面量

ingest 里的演示密钥仅用于本地跑通，生产必须走环境变量 PENGJI_DEVICE_KEYS。

P2没有自动化测试

目前只有静态自检；信用分、OPI、诊断引擎值得补纯函数单测。

云开发没就绪时，登录会降级为「本机身份 · 未连云端」，首页如实标出来——不假装核验过微信身份。

07 / 上手

三分钟跑起来

不需要云环境，也不需要后台账号。演示数据会在第一次打开时自动种下。

1

克隆仓库

用微信开发者工具直接打开项目根目录。

2

跑一遍自检

npm run check 检查 JSON、页面四件套、tabBar 一致性、事件处理器、主包体积等 10 项。

3

先选身份

农户、消费者、采购商看到的首页完全不同。选错也没关系，顶部随时切换。

4

重置演示数据

utils/store.resetAll()，或清掉本地缓存（存储键 pengji_mock_v6）。
